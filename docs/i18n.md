# Languages and writing

agendouille speaks French and English. French is the reference: write it
first, then English with the same meaning, not a word-for-word copy.

## How it works

- **Web bundles:** each module that shows text has a sibling catalog,
  `Thing.msg.ts`, built with `messages({ fr: {...}, en: {...} })` from
  `src/shared/i18n/i18n.ts`; the module calls `t('key', { name })`. The
  compiler refuses a key missing in either language. Keys are short
  camelCase names of the meaning (`addDevice`, `revokeConfirm`), not the
  text.
- **Plurals:** `{ one: '{count} appareil', other: '{count} appareils' }`,
  chosen by the `count` parameter (French counts 0 as singular; add `zero`
  when "none" reads better: `zero: 'Aucun appareil'`). Never build a plural
  with `s` added in code.
- **Placeholders:** `{name}`. Never assemble a sentence from pieces in
  code: word order differs between languages. One message per sentence.
- **Dates and numbers:** `Intl` with `locale()` from `i18n.ts`, or the
  helpers in `src/shared/core/Dates.ts` and `src/shared/render/format.ts`.
  Never `'fr-FR'` in code.
- **Server:** `internal/i18n`. Templates call `{{t "app.signin.title"}}`;
  Go code calls `i18n.T(i18n.FromRequest(r), "error.device.limit", "max",
  "20")`. Each area keeps its keys in its own `internal/i18n/catalog_*.go`,
  registered in an `init`. `TestCatalogComplete` checks both languages and
  the placeholders; `TestTemplatesKeys` checks every key a template uses.
- **The language:** the `agd_lang` cookie (the reader's choice: a select on
  the app's Moi page, FR/EN in the admin header), else the browser's
  `Accept-Language`, else French. The server writes it in `<html lang>`.
- **Not translated:** log lines, CLI output, CalDAV error bodies (read by
  programs), audit `action` codes, API error `code`s. API error
  `message`s a person reads are translated.

## French style

The audience is a family, the tone is that of a well-made product: clear,
calm, precise, polite. Not casual, not technical.

- **Vouvoiement** everywhere. Never "tu".
- **Sentence case:** only the first word and proper nouns take a capital
  ("Nouvel événement", not "Nouvel Événement").
- **Buttons are infinitive verbs** that say what happens: "Enregistrer",
  "Supprimer l'appareil", "Créer le lien". Not "OK", not "C'est fait"
  (use "Terminé" or "Fermer").
- **Titles are nouns:** "Appareils synchronisés", "Liens d'abonnement".
- **Confirmations** ask a question and state the consequence:
  "Supprimer « Pixel de Léa » ?" + "Cet appareil ne pourra plus se
  synchroniser. Cette action est irréversible."
- **Errors** say what happened, then what to do: "Ce lien a expiré.
  Demandez-en un nouveau à l'administrateur." No blame, no "Erreur :".
- **Success toasts** are short past participles: "Appareil ajouté.",
  "Modifications enregistrées."
- **Empty states** say what is missing and how to fill it: "Aucun appareil
  pour le moment. Ajoutez-en un pour synchroniser votre agenda."
- **Typography:** typographic apostrophe `’`; guillemets `« … »` with
  non-breaking spaces inside; a non-breaking space (U+00A0) before `:`,
  `;`, `?`, `!`, `»` and after `«` (narrow U+202F is fine for `;?!`);
  ellipsis `…`; times `14:05` or `14 h 05` consistently (`14:05` in the
  UI); no English words when a French one exists ("lien", not "link";
  "connexion", not "login").
- **No jargon** for the family: "synchroniser", not "sync"; "appareil",
  not "client CalDAV" (the admin UI may name CalDAV, once, where it helps).
- Numbers and dates come from `Intl`; never write "1er" by hand.

## English style

**British English**, to match the `en-GB` dates ("colour", "organise"). Sentence case, imperative buttons ("Save", "Remove device"),
contractions sparingly, no exclamation marks.
